# Re工具箱 · 字幕处理工具合集

> 把 SRT/ASS 拖进来，用插件一件一件处理，最后一次性导出——省掉字幕后期里那些重复劳动。

定位是**精修字幕之前的批处理**：批量去脏词、补说话人前缀、清重复词这类机械活交给它，导出的结果再拿去人工精校、断句和加样式特效。所以它优先保证“不破坏整体结构、不丢文件”，个别字幕块的细节瑕疵留到精修阶段顺手处理。

## 功能特性

- **拖入即用**：文件拖进主窗口就进入列表，自动去重；不需要逐个打开、也不需要把文件拖到某个 exe 上。
- **插件自动发现**：启动时扫描 `软件本体/plugins/`，读每个插件的 `manifest.json`，按分类自动生成按钮；放进去一个插件目录就多一组按钮。
- **链式处理**：插件结果先写到 `cache/output`，列表会自动切换到这批产物，于是可以接着点下一个插件，一步步往后处理。
- **统一导出**：处理满意后一次性把 `cache/output` 移到 `output/`，同名文件自动加 `_1`、`_2` 后缀，不会互相覆盖。
- **插件可安装**：拿到插件 zip 后直接在主界面安装，自动比较版本，同版本/低版本重装会先问一句。
- **内置插件**：文件名加前缀、敏感词删除 + 错词替换（含重复词压缩和可视化规则编辑器）、ASS 转透明底视频。

## 快速开始

1. **解压到可写目录**。程序要在自己目录下写 `cache/output`、`cache/temp`、`output` 和规则文件，放 `C:\Program Files` 之类只读位置会失败。
2. **双击主程序 exe**。发布包是 `Re工具箱 - vX.Y.Z.zip`（另有「- 无插件」版），解压后双击里面的 `Re工具箱 - vX.Y.Z.exe`。窗口底部会显示版本号与更新日期。
3. **拖入文件**。把这一集的 SRT 全部选中拖进大白框；拖错了可以选中后点「移除选中」。
4. **点插件按钮**。按处理顺序依次点，例如先「srt关键词替换」再「srt加前缀」。关键词替换与 ASS 插件处理完会弹窗汇总，「srt加前缀」不弹窗，结果看右侧日志。
5. **点「导出」**。文件落到 `output/` 里；点「导出并打开位置」会顺手打开资源管理器。

> 开发模式运行（源码）见下方「开发与构建」。

## 使用说明

### 文件与列表

- 列表只是“待处理文件清单”，项是**原始路径字符串**，不按扩展名过滤；具体处理什么由插件自己判断（两个 SRT 插件都只处理 `.srt`，其余文件跳过并在日志里说明）。
- **请不要拖入同名文件**：缓存按文件名（basename）存放，不同目录的同名 SRT 会互相覆盖。
- 「移除选中」删掉列表里选中的项（支持多选）；「清空所有」清空列表**并清空 `cache/output`**。
- 插件运行成功后，列表会被插件返回的产物路径整体替换（即 `cache/output` 下的文件），这正是链式处理的基础。此时列表里已经不是你最初拖入的原始文件了。
- 右侧日志面板会实时显示插件输出，可用「清空日志」清屏。

### 插件按钮

- 按钮按 `manifest.json` 的 `category` 分组显示，每组一行；同一插件可以提供多个按钮（例如「srt关键词替换」和「修改配置」）。
- 点按钮后主程序会**同步等待插件跑完**——大批量文件或 ASS 渲染时窗口会短暂“未响应”，属于正常现象，不要重复点击。
- 插件出错时，会把错误信息弹窗显示；日志面板里还有完整输出。
- 「重启刷新」＝重新扫描插件目录并重建窗口，等同重启：**会清空 `cache/output`**，需要保留的中间产物请先导出。

### 导入插件

1. 把插件 zip **拖进文件列表**（插件单独发布，形如 `srt关键词替换-v1.3.0.zip`，根目录自带 `manifest.json`）；
2. 点「导入插件」。

规则与表现：

- zip 根目录必须有 `manifest.json`（要求 `name`、`version`；没写 `plugin_id` 就用 `name` 当目录名），解压到程序目录下的 `plugins/<plugin_id>/`（源码模式下即 `软件本体/plugins/<plugin_id>/`）；
- 新版本自动安装；版本相同或更低时弹窗询问是否重装，选「否」什么都不做；
- **只有真正装上了插件**才会移除该 zip 并刷新按钮区；安装失败（非 zip、缺 `manifest.json`、文件损坏）或用户取消重装时，列表不变、窗口不变、已处理的中间产物也不会被清掉；
- 失败时会弹「以下文件未导入」，把失败的文件列出来。

### 导出

- 「导出」：把 `cache/output` 里的文件全部移动到 `output/`，并清空文件列表；
- 「导出并打开位置」：同上，再打开 `output/` 所在目录；
- 目标位置已有同名文件时，自动改用 `name_1.srt`、`name_2.srt` 这样的递增后缀。

### 规则配置（重点）

**规则不在 `config.json` 里。** 历史版本的 README 写错了，这里明确一下：

| 文件 | 作用 |
|---|---|
| `软件本体/plugins/srt关键词替换/subtitle_rules.json` | **真正的处理规则**（删除词、重复词、替换词） |
| `软件本体/plugins/srt关键词替换/default_subtitle_rules.json` | 默认规则模板；工作文件缺失或读不出来时用它兜底 |
| `软件本体/config.json` | **只存程序名称、版本、更新日期、作者信息**，与处理效果无关 |
| `软件本体/plugins/srt关键词替换/subtitle_rules.pkl` | 自动机缓存，自动生成，不用手工维护 |

> 上表是源码模式的路径；发布包里把 `软件本体/` 换成程序所在目录即可（即 `plugins/srt关键词替换/subtitle_rules.json`）。

**推荐改法**：点主界面「修改配置」按钮，打开内置的规则编辑器（PyQt5 界面，需要装 `PyQt5`）。界面里一棵树的三个顶层节点分别对应 Delete / Repeat / Replace，右键可以增删改、切换启用；保存后下次处理会自动生效——缓存按规则内容哈希校验，JSON 一变就会自动重建，不需要手工删 `subtitle_rules.pkl`。

**手工编辑 JSON 的注意事项**：

1. 用 UTF-8 保存；改之前先备份 `subtitle_rules.json`。
2. **格式写错会被默认规则覆盖**：程序读不出来时会尝试用 `default_subtitle_rules.json` 覆盖工作文件，你的改动就没了。
3. **升级「srt关键词替换」插件也会覆盖规则**：插件 zip 里自带 `subtitle_rules.json`，安装时会先删掉旧插件目录再解压（同版本确认重装同理）。自己调过规则的话，升级前先把 `subtitle_rules.json` 复制到别处，装完再放回原位即可。

规则文件的结构就三块：

```json
{
  "delete": {
    "profanity": ["傻逼", "卧槽"],
    "others": ["呃", "uh"]
  },
  "repeat": [
    {
      "word": "哈",
      "enabled": true,
      "max_times": 3,
      "interval": { "enabled": false, "min_consecutive": 3, "separator": " " }
    }
  ],
  "replace": [
    {
      "word": "我的世界",
      "type": "group",
      "enabled": true,
      "items": [
        { "word": "卡慕", "enabled": true, "source": ["卡布", "卡莫", "卡木"] }
      ]
    }
  ]
}
```

各字段含义：

- `delete.profanity`：删除**并计数**（会计入「文明小助手」）；
- `delete.others`：**仅删除、不计数**；
- `repeat`：压缩连续重复词。`enabled` 是整条规则的开关；`max_times` 是最多保留几次；`interval.enabled` 只控制“要不要在保留的词之间插分隔符”，`min_consecutive` 按**压缩前**的连续次数判断。只识别无空格、无标点的连续同词（`哈哈哈哈` 算，`哈 哈` 不算）。
- `replace`：分组树。`type: "group"` 只用来组织结构（可嵌套、可整组禁用），叶子节点用 `source` 列出“听错的写法”，`word` 是正确写法。同一组里 `source` 不要重复，跨组重复时后面遍历到的会覆盖前面的。
- `type: "regex"` **尚未实现**，写了也不会生效。
- 匹配**区分大小写**，英文人名/缩写要把各种大小写变体都列进 `source`。

## 插件列表

| 插件 | 功能 | 状态 | 备注 |
|---|---|---|---|
| `srt加前缀` | 用 SRT 文件名作为说话人，给每条字幕加上「文件名：」前缀 | 可用 | 按空行分块，多行字幕只在第一行加；按当前文件名幂等，重复点不会叠加（`主持人：` 这类其他前缀会叠成 `文件名：主持人：…`）；`{\an8}` 这类行首样式标签会被前缀顶到标签前面 |
| `srt关键词替换` | 删除敏感词、替换常见错词、压缩重复词；处理完弹窗给出「文明小助手」排名（按被删敏感词次数取前 10） | 可用 | 附带「修改配置」按钮打开规则编辑器，见上文「规则配置」 |
| `ass转码透明底视频` | 把 ASS 字幕渲染成带 Alpha 通道的 MOV（QuickTime Animation / `qtrle` + `argb`） | **实验性** | 需自备 FFmpeg：放到 `plugins/ass转码透明底视频/ffmpeg/bin/ffmpeg.exe`；仓库与发布包都未附带，代码未做端到端验证 |
| `测试插件` | 「测试弹窗」「测试报错」两个按钮，用来验证插件协议与异常链路 | 仅调试 | 无实际功能，正式使用可以忽略 |

## 开发与构建

### 环境准备与安装

- 系统：Windows（用到 `notepad.exe`、`explorer.exe`、`CREATE_NEW_CONSOLE` 与 TkDnD 原生库）
- Python：3.11.x（代码使用 `match/case`，低于 3.10 无法运行）

只运行工具箱（runtime 依赖，含 PyQt5 规则编辑器）：

```bash
pip install -r requirements.txt
```

开发、测试或打包（在 runtime 之上追加 pytest 与 PyInstaller）：

```bash
pip install -r requirements-dev.txt
```

### 开发模式运行

```bash
python 软件本体/插件调度主程序.py
```

插件由主程序用当前 Python 解释器启动，所以主程序必须跑在装好依赖的环境里。测试用 `pytest tests/`。

### 打包 exe

打包命令见工作区根目录的 `打包exe指令.txt`（该文件不入库，位于本仓库的上一级目录）；命令需在 `软件本体/` 目录内执行，`icon.ico` 与 `插件调度主程序.py` 都是相对路径。

> 该指令里的 `--name "v1.1.0"` 尚未跟随当前版本更新，打包前请自行改成实际版本号。

## 已知限制

- **ASS 插件需要自备 FFmpeg**：路径固定为 `plugins/ass转码透明底视频/ffmpeg/bin/ffmpeg.exe`，仓库该目录是空的，发布包也未附带；缺失时会直接报 `不是, 你 FFmpeg 呢`。该插件也未出现在现有发布产物中，分发方式待定。
- **插件运行期间主界面会阻塞**：主程序同步等待插件进程结束，没有进度条、超时和取消；ASS 渲染或几百个文件时会显示「未响应」。
- **SRT 前缀插件的边界**：按空行分块，块内没有时间轴的块原样保留、不加前缀；`{\an8}` 之类行首样式标签会被前缀顶到标签前面（`ep01：{\an8}…`），需要保留字幕定位的话请手工调整（这类情况出现得少，作者已决定不做标签特殊处理）；非 UTF-8（如 GBK）编码的字幕会解码失败，该文件不产出、计入失败——先把字幕转成 UTF-8 再处理即可（作者已决定不做编码回退）；列表里扩展名是 `.srt` 但文件已被删除或换成目录的，也会计入失败并提示「文件不存在或不可读」。
- **同名文件会互相覆盖**：插件输出统一写到 `cache/output/<basename>`，不同目录的同名 SRT 处理后会只剩一个。
- **规则大小写敏感**，且 `regex` 规则类型尚未实现。
- **程序目录必须可写**（`cache/`、`output/`、规则文件、插件日志都在程序目录下）。
- 打包环境下规则编辑器「新建」的保存路径可能落在临时解压目录，**未在打包环境验证**。
