### 28. 单条字幕纯重复去重（关键字替换插件新功能）

**背景**：有些字幕整行是无意义的重复（`哈哈哈哈哈哈`、`哦哦哦哦哦哦哦`、`嘿嘿哈哈嘿嘿哈哈`），现有 `repeat` 只能处理**词表里配置过的词**，覆盖不到这种整行垃圾。新增「循环重复」检测：整行（或行内某一段）是同一单元的循环且达到字数阈值时，按单元长度归一化。

**需求（2026-10-23 作者定稿）**：

1. **判定条件**
   - 长度阈值 **≥ 6 个字**（可配；**等于阈值即触发**，不是「超过」）。
   - 字数按去掉首尾空白后的**字符数**统计；标点、字母、数字一律当普通字符，不做剥离、不当分隔符。
   - 「循环」按**最小周期**判定：若 `s` 由单元 `u` 重复 n 次（n ≥ 2）构成且 `u` 取最小周期，则 `len(u)` 为单元长度。**最小周期优先**——`呵呵呵呵` 的单元是 `呵`（周期 1），走单字分支，不按 `呵呵`；`嘿嘿哈哈嘿嘿哈哈` 的单元是 `嘿嘿哈哈`（周期 4），走多字分支。
2. **归一化输出**（分隔符固定为一个半角空格）
   - 单元长度 1 → 保留 `single_keep` 个：`哈哈哈哈哈哈哈` → `哈 哈 哈`
   - 单元长度 ≥2 → 保留 `multi_keep` 个：`嘿嘿哈哈嘿嘿哈哈` → `嘿嘿哈哈 嘿嘿哈哈`
   - 不设单元长度上限（作者：实际素材里几乎不会出现长周期误判）。
3. **严格 / 非严格两种模式**（配置开关，默认严格）
   - **严格（默认）**：整行去首尾空白后必须**恰好等于** `u × n`，有任何额外字符（如 `哈哈哈哈草`）都不处理；此时判断的是**整行长度**。
   - **非严格**：允许行内有其他内容，扫描行内**最长的纯循环片段**，判断的是**该循环片段的总长度**（≥ `min_chars`），不是整行长度；只替换该片段，前后文字原样保留；多段等长时取靠前的一段。
4. **附带行为（作者新增）**：**导出时每行去掉首尾空格**，对全部字幕文本行生效，与该功能开关无关；空行保持为空，行首样式标签（`{\an8}`）不动。
5. **配置与默认值**：写在 `subtitle_rules.json`，规则编辑器「修改配置」可看可改——启用开关、严格模式开关、单条字幕超过多少字、单字循环保留多少次、多字循环保留多少次。**默认启用**。

**配置形态（拟）**：

```json
"line_dedupe": {
  "enabled": true,
  "strict": true,
  "min_chars": 6,
  "single_keep": 3,
  "multi_keep": 2
}
```

- 新增**根键**，不动 `repeat` 的数组结构；旧规则文件缺该键时按内置默认值处理（即上表数值）。
- 校验：`min_chars ≥ 2`、`single_keep ≥ 1`、`multi_keep ≥ 1`（建议上限 20），非法值回落默认并在编辑器里提示。

**处理顺序**：`delete/replace → repeat → line_dedupe（最后统一去首尾空格）`。`repeat` 优先——配过词的行会先被压短，通常不再满足阈值；新功能只兜底剩余的长重复行。反过来前置会让 `repeat` 对已插空格的文本二次匹配，行为不可预测。

**与现有 `repeat` 的关系**：`repeat` 是**词级、字典驱动**（`word` + `max_times` + 可选 `interval` 分隔，只在命中词表时压缩）；本功能是**行级、结构驱动**（任意单元，靠阈值与纯重复判定）。两者互补，不共用配置。

**实现要点**：
- `process_text()` 末尾逐行处理（保留原换行风格）；跳过空行、纯序号行、含 `-->` 的时间轴行；不改变行数。
- 最小周期用「`s + s` 中从下标 1 起查找 `s`」或 KMP 实现；全同字符时周期为 1。
- 非严格模式用回溯正则（如 `(.+?)\1+`）逐段扫描，取循环总长度最长的一段；替换时只动该段。
- `CACHE_SCHEMA_VERSION` 递增（行为依赖新配置，否则旧 pkl 不会重算）。
- 去首尾空格放在整条处理链的最后统一执行。

**已确认口径（2026-10-23，作者拍板）**：
- 单元判定用最小周期，`呵呵` 按单字算 ✔
- 阈值是 `≥ 6`，标点当普通字符，只去首尾空白 ✔
- 加严格/非严格开关，默认严格；非严格判断循环片段长度 ✔
- 默认启用 ✔
- 不设单元长度上限 ✔
